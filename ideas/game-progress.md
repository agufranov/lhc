# Превращение симулятора в игру: знания и прогресс

Этот файл хранит решения и состояние работ в ветке `game`. Он не заменяет
техническую документацию в `docs/`: сюда попадает направление разработки,
проверяемые критерии игровых срезов и то, что уже сделано.

## Цель

Превратить существующую операторскую песочницу в постепенно раскрывающуюся игру,
не заменяя физическую симуляцию условными переходами между состояниями.

Игрок должен понимать:

- чего он пытается добиться сейчас;
- какое действие доступно и почему;
- что физически произошло после этого действия;
- как отдельные операции складываются в работу ускорительного комплекса.

Полная постановка задачи и открытые вопросы находятся в
`ideas/game-question.md`. Возможности исходного симулятора описаны в
`ideas/sim-state.md`.

## Неподвижные основания

- Пучок остаётся непрерывно движущимся объектом общей физической модели.
- Инжекция, extraction, ramp, cogging, столкновение, потеря и dump продолжают
  происходить через существующие механизмы `World`.
- Игра не исправляет ошибку игрока скрытым interlock: неправильное действие
  должно оставаться физически возможным и давать видимый результат.
- Sandbox сохраняет полный набор возможностей исходного симулятора.
- Guided-режим управляет подачей информации и доступностью интерфейса, а не
  подменяет состояние машины.
- Визуальная композиция комплекса остаётся важной частью проекта. Любая новая
  панель должна оставлять машине измеренное место и проверяться в браузере.
- Мобильный экран считается целевой средой, а не уменьшенной копией desktop UI.

## Первый вертикальный срез: первые столкновения

Первый срез должен провести нового игрока через уже существующую физическую
цепочку:

1. Разогнать находящийся в SPS batch с 26 до 450 GeV.
2. Извлечь его через TI 2 в beam 1 LHC.
3. Подготовить следующий batch и ввести его через TI 8 в beam 2.
4. Разогнать LHC до 6,8 TeV.
5. Выполнить cogging и получить столкновения в детекторах.

### Правила среза

- Страница открывается непосредственно в работающей симуляции, без отдельного
  главного меню.
- На каждом шаге интерфейс показывает одну текущую цель и одно осмысленное
  следующее действие.
- Ожидание реального процесса — доставки, ramp, полёта или cogging — является
  отдельным видимым состоянием, а не мгновенным пропуском.
- До завершения знакомства случайные incidents отключены, чтобы обучение не
  разрушалось событием, которое ещё не было объяснено.
- Игрок в любой момент может выйти в sandbox и получить полный пульт.
- Автоматизированные проверки исходного симулятора запускаются в sandbox, чтобы
  guided UI не менял смысл прежних измерений.

## Критерии готовности первого среза

- Новый игрок видит цель сразу после загрузки.
- Нерелевантная телеметрия и команды не образуют стену данных в guided-режиме.
- Штатная последовательность до первых столкновений полностью проходится мышью
  и касанием.
- На desktop панели не перекрывают машину и друг друга.
- На узком portrait-экране цель, машина и текущая команда помещаются без
  горизонтальной прокрутки.
- Переход в sandbox возвращает все прежние панели, команды и incidents.
- `typecheck`, `check`, `check:render` и `check:page` остаются зелёными; новый
  видимый режим имеет собственные browser assertions.

## Второй вертикальный срез: Production Shift

- Смена продолжается из первого столкновения без reset и считает только данные, набранные
  после своего старта.
- Цель: `0.030 fb⁻¹` за три минуты wall time, хотя бы один `operator dump` и stable beams в
  более позднем fill.
- После dump игрок возвращает пустой LHC к 450 GeV и повторяет настоящую цепочку SPS → TI 2 /
  TI 8 → LHC ramp → cogging. Сценарного создания пучков нет.
- На desktop во время производства раскрывается RUN со спектрами; на mobile остаются цель,
  таймер, progress данных и крупное решение о dump.
- По окончании score замораживается, оставшиеся beams штатно уходят в оба dump, затем появляется
  отчёт по данным, availability, измеренному turnaround, dump, quench и damage.

## Проверки первого среза

- `npm run typecheck` — пройден.
- Полный `check` — пройден.
- Полный `check:render` — пройден.
- Полный `check:page` — пройден на старых desktop-viewport, в новом guided-сценарии и на
  portrait-экране 390×844.
- `npm run build` — production-сборка пройдена.
- Из-за заполненного диска `check`, `check:render` и `check:page` запускались теми же esbuild-
  скриптами через pipe в Node без записи промежуточного bundle в `node_modules/.cache`.

## Наблюдения

- Один batch уже находится в SPS при старте. Поэтому первый осмысленный вводный
  шаг — ramp SPS до 450 GeV, а не создание пучка из пустоты.
- Текущий mobile CSS скрывает обе телеметрические rails, но оставляет полный
  многострочный пульт. На portrait-экране пульт выходит за правую границу и
  забирает значительную часть высоты. Простого уменьшения desktop UI недостаточно.
- Штатные browser-сценарии находят команды по тексту. Sandbox должен сохранять
  текущие подписи или проверки нужно будет переводить на стабильные идентификаторы.
- Команды получили стабильные `data-action`, поэтому прогрессия и browser checks
  больше не обязаны распознавать смысл кнопки по её видимой подписи.
- В измеренном viewport 390×844 guided-панель занимает `x=10..380`, текущий
  пульт — тот же диапазон, горизонтальный размер документа равен 390 px. Верхняя
  точка геометрии машины находится на `y=408`, ниже панели, заканчивающейся на
  `y=216`, а пульт начинается на `y=778`.
- Первый автоматический проход достиг ненулевой светимости через состояния
  `beam-1-ramp → beam-1-extract → beam-2-fill → beam-2-ramp → beam-2-extract →
  lhc-ramp → cog → commissioning-complete`.
- Сквозной Production Shift browser-test продолжает тот же `World`, набирает данные, выполняет
  operator dump, возвращает LHC к injection energy, заново проводит оба batch через SPS и
  transfer lines, делает ramp и cogging и получает `production-passed` только после новой
  ненулевой светимости.
- Для второго среза повторно пройдены `typecheck`, полный `check`, `check:render`, production
  build и полный `check:page` на четырёх desktop-размерах и portrait 390×844.
